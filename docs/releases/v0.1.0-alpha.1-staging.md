## What this is and is not

Read these before relying on the result.

- **It is a scripted rehearsal, not an independent installation test.** The
  same agent that prepared the release ran it. The documentation-only
  installation tests by people outside development are a beta requirement and
  have not happened.
- **The host was a shared development VM, not a dedicated or freshly
  provisioned one.** It runs unrelated containers. The rehearsal ran as its own
  Compose project on loopback ports and was removed afterwards.
- **Host reboot and Docker daemon restart were not rehearsed**, because they
  would have interrupted the other workloads on that host. Recovery from either
  is untested.
- **The images were built on the host from source.** No image had been
  published, so the registry pull path was not exercised. The host has no
  BuildKit plugin, so they were built with Docker's legacy builder on the same
  digest-pinned base image as `make release-image`. They are not the image that
  CI builds, scans, signs, and publishes for the tag.
- **All request content was synthetic** and the provider was a mock that echoes
  the last user message. No real provider, model, or personal data was involved.
- **Single node, default in-memory vault, default policy.** The experimental
  Responses and Messages endpoints were off.

## Procedure

The scripts and the complete output are in
[`v0.1.0-alpha.1-staging/`](v0.1.0-alpha.1-staging/):

| File | Purpose |
|---|---|
| `rehearse.sh` | The whole run: build, deploy, probe, failure cases, log checks |
| `probe.py` | Black-box HTTP checks against the running gateway |
| `mock_provider.py` | OpenAI-compatible mock that records what the gateway sent it |
| `rehearsal.override.yaml` | Compose override: selects the image tag and adds the mock |
| `rehearsal.log` | Unedited output of `rehearse.sh` for this run |

It was started with:

```bash
bash rehearse.sh cf044a85485e1703ac09f6741bb711da3ddb5c4e 78af9a400f48bfcfd8761d628a7a67d20f7e5d8d
```

Each version was built from its own checkout and run from that checkout's
`compose.yaml`:

```bash
git checkout --detach <commit>
. deployment/docker/base-image.env
docker build -f deployment/docker/Dockerfile \
  --build-arg BASE_REF="$BASE_IMAGE@$BASE_DIGEST" -t cloakspan-rehearsal:<commit> .
REHEARSAL_IMAGE=cloakspan-rehearsal:<commit> \
  docker compose -p cloakspan-rehearsal -f compose.yaml -f ../rehearsal.override.yaml up -d --no-build
```

Configuration was a generated `.env`: `SAG_ENVIRONMENT=production` (from
`compose.yaml`), two API keys for two tenants, fresh vault and token keys, both
provider URLs pointing at the mock with `SAG_EGRESS_ALLOW_PRIVATE=true`,
`SAG_REQUEST_TIMEOUT_SECONDS=20`, `SAG_RATE_LIMIT_PER_MINUTE=120`, and a
generated `SAG_METRICS_TOKEN`. The same `.env` was used for both versions; the
previous commit ignores the settings it does not know.

## Results

### Install, upgrade, rollback, roll forward

| Step | Running commit | Ready after | Checks |
|---|---|---|---|
| 1. Install | `cf044a8` | 1.6 s | 18 of 18 |
| 2. Upgrade | `78af9a4` | 1.6 s | 26 of 26 |
| 3. Roll back | `cf044a8` | 1.6 s | 13 of 13 |
| 4. Roll forward | `78af9a4` | 1.6 s | 17 of 17 |

"Ready after" is the time from `docker compose up -d` returning until `/readyz`
answered 200, polled every half second. Compose recreated only the gateway
container, and the gateway was unavailable while it was replaced. By the log
timestamps a whole replacement took about three seconds, with no traffic.

The checks repeated at every step, against the running container:

- `/healthz` and `/readyz` answer 200.
- A request with no credential and one with an unknown key get 401.
- A clean request is forwarded (`allow`).
- A request containing a synthetic email address and IBAN is forwarded with
  both replaced by tokens (the mock received neither value), and the reply the
  client receives has both restored (`transform`, 2 detected, 2 restored).
- A request containing an example AWS access key gets 403 `blocked_by_policy`
  and the mock receives nothing.
- A 1.2 MB body gets 413 and malformed JSON gets 400; the mock receives nothing.

After the install and after the upgrade, the container was also checked for
its hardening: uid 10001, read-only root filesystem, all capabilities dropped,
`no-new-privileges`, a 1 GiB memory limit, a failed write to `/`, a healthy
health check, and a port published on loopback only.

**Tokens do not survive a version change, as documented.** After the upgrade
and again after the rollback, the tokenised text from the previous process was
sent back in the same conversation. Neither value was restored. The audit event
recorded `tokens_restored: 0` and `tokens_refused_by_reason: {"not_minted": 2}`.
The operations guide predicted `vault_miss` for this case; it has been
corrected.

On the previous commit `/metrics` answered 404, as expected for a version
without the route.

### Settings new in this release

Checked after the upgrade and again after the roll forward:

- `/metrics` answers 401 without a token and 401 with a tenant API key. With
  its own token it answers 200 with 58 lines, none containing the synthetic
  values, the conversation id, or the model name.
- The second tenant's key was sent requests in a tight loop. With a limit of
  120 per minute, 132 were admitted before the first 429, which carried
  `Retry-After: 1`. The bucket starts with one minute's allowance and refills
  at two per second, so the extra 12 match the roughly six seconds the loop
  took. The first tenant's key was unaffected.
- Responses carry `X-Request-Id`.

### Failure cases

All on the rehearsed commit.

| Case | How it was caused | Observed |
|---|---|---|
| Gateway process dies | `kill -9` of the container's init process from the host | Container restarted by `restart: unless-stopped` and `/readyz` was 200 again within 2 s; restart count 1; all 10 checks pass afterwards |
| Provider unreachable | Mock container stopped, so its name no longer resolves | 502 `upstream_error` after 5.0 s; audit `error: egress_blocked`, `provider: none`; `/readyz` stays 200; a credential is still blocked with 403 |
| Provider hangs | Mock container paused, so it accepts connections and never answers | 504 `upstream_error` after 20.0 s, the configured provider deadline; audit `error: provider_timeout`; `/readyz` stays 200; no synthetic value in the error body |
| Provider returns | Mock started or unpaused | All 10 checks pass |
| Required values missing | `docker compose config` with an empty environment | Compose refuses: `required variable SAG_API_KEYS is missing a value` |
| Vault key missing | Image started in production mode without `SAG_VAULT_KEY` | Exit 1: `ConfigurationError: Set SAG_VAULT_KEY to a persistent secret of at least 32 decoded bytes.` |
| Weak metrics token | Image started with `SAG_METRICS_TOKEN=short` | Exit 1: `ConfigurationError: Set SAG_METRICS_TOKEN to at least 32 random characters` |

The provider-hang case was run by hand after `rehearse.sh` finished, so it is
not in `rehearsal.log`. It was `docker pause` on the mock container, one
request carrying the synthetic email address, `docker unpause`, and then the
basic checks through `probe.py`.

A provider that refuses connections outright was not tested: stopping the mock
removed its DNS name, which the gateway treats as a destination it cannot
validate and refuses before connecting.

## What the rehearsal changed in the documentation

- `docs/operations.md` told operators to upgrade with `docker compose pull`.
  The bundled `compose.yaml` builds from the checkout, so there is nothing to
  pull. The upgrade and rollback sections now describe a build from the
  checkout, and say which form of it the rehearsal used.
- The same page predicted `vault_miss` refusals after an upgrade. The observed
  reason was `not_minted`.

## Not covered

- Host reboot and Docker daemon restart.
- The published container image and the registry pull path.
- A build with BuildKit on the staging host.
- A provider that refuses connections, returns errors, or returns malformed
  bodies. These are covered by unit tests, not by this rehearsal.
- Load, sustained operation, memory growth, and the concurrency cap under
  real contention.
- The detector deadline, which needs a pathological input to trigger.
- Local-model routing, custom filters, NER, key rotation, and the experimental
  Responses and Messages endpoints.

The rehearsal must be repeated for each later release, from the previous
release rather than from a previous commit.
